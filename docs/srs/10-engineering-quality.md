# 10. Engineering quality (ENG)

Cairn is security-critical infrastructure written from scratch. These
requirements define the quality bar for the codebase and the delivery pipeline.

## 10.1 Code

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Ver  |
| ------ | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| ENG-01 | P0  | Every toolchain the repository builds with MUST be fixed to an exact version in the repository: a `rust-toolchain.toml` naming an exact Rust release for the product, an exact dated nightly for the jobs that need one (`cargo-fuzz`, Miri, ThreadSanitizer), exact Node.js and package-manager versions for the browser room view client's build, and Go's `toolchain` directive for the repository tooling. Release builds MUST strip build paths (Rust's `--remap-path-prefix`, Go's `-trimpath`), embed VCS information, and link no dynamic library beyond the operating system's (Go: `CGO_ENABLED=0`); the core executable links none at all on Linux (CON-02). | I    |
| ENG-02 | P0  | Product code MUST be organised as a Cargo workspace: one binary crate per executable and library crates with one responsibility each (e.g. `adapter-claudecode`, `ingest`, `provenance`, `redaction`, `flag`, `store`, `payload`, `search`, `recall`, `envelope`, `landmark`, `pin`, `restore_block`, `kernel`, `audit`, `configuration`, `administration`, `mcp`, `hook`), and the browser room view client as one TypeScript package that depends on nothing of the core but its generated types. Allowed dependency directions MUST be declared and enforced by a CI check.                                                                                          | I, T |
| ENG-03 | P0  | Crates MUST NOT keep mutable global state (no `static mut`, no global cell or lock containing mutable state). All I/O MUST go through traits injectable in tests. Every blocking operation MUST take a deadline, carried directly or by a cancellation signal that a deadline fires. Code that computes derived artifacts MUST NOT read the wall clock or randomness (I10).                                                                                                                                                                                                                                                                                             | I, T |
| ENG-04 | P0  | Errors MUST keep their cause chain (each error type exposes its cause); each failure class that feeds a counter (OPS-01) MUST have a typed error. Panics MUST NOT cross crate boundaries; release builds MUST unwind on panic, and the hook handler and MCP entry points MUST catch it (`catch_unwind`), fail open, and audit.                                                                                                                                                                                                                                                                                                                                          | I, T |
| ENG-05 | P0  | Logging MUST use `tracing` with structured fields, and log fields MUST pass through redaction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | T    |

## 10.2 Testing

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Ver  |
| ------ | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| ENG-06 | P0  | A crash-consistency test MUST kill Cairn processes at randomized points during ingestion, purge, migration, and rebuild — at least 10,000 iterations per nightly job — and verify all invariants after each.                                                                                                                                                                                                                                                                                         | T    |
| ENG-07 | P0  | Coverage-guided fuzzing (`cargo-fuzz`) MUST cover the transcript parser, hook input decoder, `event_search` query parser, envelope encoder, field sanitizer, redactor, and configuration parser, running continuously in nightly CI with the corpus committed. Any fuzz crash is a release blocker.                                                                                                                                                                                                  | T    |
| ENG-08 | P0  | Property-based tests MUST cover: within each writer's log, `seq` strictly increasing and gap-free, so that no two events share an address (writer, `seq`); ingest-twice equals ingest-once; rebuild reproduces derived artifacts exactly; envelope encoding round-trips any byte sequence; sanitized fields never contain restore delimiters.                                                                                                                                                        | T    |
| ENG-09 | P0  | Data races MUST be excluded: safe Rust rejects them at compile time, and every `unsafe` block that shares memory between threads MUST run under Miri or ThreadSanitizer in CI. A nightly soak test MUST run 50 concurrent writers to 1M events and verify invariants, among them that no two events share an address (writer, `seq`) and no `seq` is duplicated or skipped within a writer's log.                                                                                                    | T    |
| ENG-10 | P0  | Golden-file tests MUST compare the exact bytes of restore blocks and envelopes for fixture records with committed files (INJ-06).                                                                                                                                                                                                                                                                                                                                                                    | T    |
| ENG-11 | P0  | Line coverage MUST be ≥ 90% for security-sensitive crates (`provenance`, `redaction`, `flag`, `search`, `envelope`, `restore_block`, `pin`, `landmark`, `configuration`) and ≥ 80% overall.                                                                                                                                                                                                                                                                                                          | A    |
| ENG-12 | P0  | The end-to-end suite MUST run each component's entry point confined to its boundary: all network denied for the core (the hook handlers and the CLI, each harness adapter's transcript and hook part among them, the MCP server, the kernel worker and the TUI); all but loopback denied for the room-view component and the launcher; each of the peer, publish and bridge components confined to its register rows. It MUST fail on any socket outside the boundary the register assigns (SEC-19). | T    |
| ENG-13 | P1  | Mutation testing SHOULD run on security-sensitive crates with a mutation score ≥ 70%.                                                                                                                                                                                                                                                                                                                                                                                                                | A    |
| ENG-14 | P0  | Tests MUST run with isolated `HOME` and `CAIRN_HOME`; a guard MUST abort any test that touches the real `HOME`, a real Cairn home or real Claude Code configuration. The repository MUST NOT contain agent instruction files that direct agents to run destructive commands against non-isolated state.                                                                                                                                                                                              | T, I |
| ENG-15 | P0  | A benchmark suite MUST cover NFR-01..05, with a CI gate failing on a statistically significant regression greater than 10%.                                                                                                                                                                                                                                                                                                                                                                          | T    |

## 10.3 Static analysis and supply chain

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Ver |
| ------ | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| ENG-16 | P0  | CI MUST gate on `cargo clippy` with warnings denied, `cargo fmt --check`, `cargo-deny` (licenses, bans, sources), `cargo-audit` (no known vulnerabilities in the dependency tree), the TypeScript compiler in strict mode and a linter for the browser room view client, and custom checks; repository tooling written in Go keeps `go vet`, `staticcheck`, `gosec`, `errcheck` and `govulncheck`. Every crate that parses content from outside the trusted sources or decides trust MUST carry `#![forbid(unsafe_code)]`. A build-time check MUST fail when code that computes derived artifacts reads a clock or randomness (I10), or when restore content is built from anything but trusted text (SEC-07, I2). Build-time evidence MUST show, per component, what network and program-start reach the code it can execute has, dependencies and code that runs as the process starts included: no network for the core, and no program start except its own kernel worker; program start only in the launcher; listening only in the room-view component (loopback only), the launcher (loopback, or a local endpoint only the same OS user can reach), the peer component and the publish component; off-machine connections only in the peer, publish and bridge components. CI MUST fail when that evidence is missing or shows more reach than the register (§6.3) grants, whatever the packaging. | T   |
| ENG-17 | P0  | Contract tests MUST replay recorded hook inputs and transcripts for every supported Claude Code version (NFR-11), and a nightly live end-to-end test MUST drive real Claude Code headlessly through compaction, restore, and recall.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | T   |
| ENG-18 | P0  | Every direct dependency MUST be justified by an accepted ADR (ENG-26) that states its purpose, license, maintenance status and the alternatives considered, and `DEPENDENCIES.md` MUST list those ADRs. Licenses MUST be on an allow-list (Apache-2.0, MIT, BSD, ISC). The target is ≤ 10 direct dependencies. Updates MUST go through reviewed pull requests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | I   |
| ENG-19 | P0  | Release builds MUST be reproducible: two independent builders MUST produce bit-identical artifacts, verified in the release pipeline.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | T   |
| ENG-20 | P0  | Release artifacts MUST be signed with Sigstore (keyless), carry SLSA Build Level 3 provenance and an SPDX SBOM, and be published with a signed checksum file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | T   |

## 10.4 Process

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Ver  |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| ENG-21 | P0  | All changes MUST land through reviewed pull requests with signed commits and no direct pushes to the main branch. Every pull request MUST be approved by a reviewer other than its author, and that reviewer MAY be an AI agent. Changes to the requirement text (`docs/srs/`), or to what enforces it (the requirement–scenario gate, CI, the lint and coverage configuration, the agent instructions and `CODEOWNERS` itself), MUST also be approved by the stakeholder `CODEOWNERS` names. Changes to security-sensitive crates MUST have two approvals, including a designated security reviewer. AI-generated changes MUST be labelled. | I    |
| ENG-22 | P0  | Every privacy or data-flow statement in the documentation MUST reference the test that proves it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | I    |
| ENG-23 | P0  | Releases MUST follow semantic versioning, ship a changelog and upgrade notes, and test migrations from every previous minor version. Deprecations MUST last at least one minor release.                                                                                                                                                                                                                                                                                                                                                                                                                                                      | T, I |
| ENG-24 | P0  | The repository MUST contain `SECURITY.md` with a private disclosure channel and a 90-day coordinated disclosure policy. Security fixes MUST be backported to the latest minor release.                                                                                                                                                                                                                                                                                                                                                                                                                                                       | I    |
| ENG-25 | P1  | The project SHOULD have at least two active maintainers and an incident-response runbook before v1.0 general availability.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | I    |
| ENG-26 | P0  | Every design decision MUST be recorded in one ADR file under `docs/adr/`, named for its unique id, with a title, a status (proposed, accepted or superseded) and a one-line summary. A decision that changes MUST be recorded as a new ADR, and the ADR it replaces MUST be marked superseded and name the ADR that supersedes it.                                                                                                                                                                                                                                                                                                           | T    |
| ENG-27 | P0  | Every check that keeps the specification, its scenarios and the repository's records in step MUST have a registered drift case. CI MUST inject each drift into a copy of the repository and fail when the check does not catch it.                                                                                                                                                                                                                                                                                                                                                                                                           | T    |
| ENG-28 | P0  | An agent's approval (ENG-21) MUST be posted by a GitHub App identity that authors no change, from a workflow that runs as the default branch defines it, never as the pull request under review defines it. The reviewing agent MUST have no credential that can approve or write. A separate step MUST approve only when the agent's review outcome (its `verdict` field) approves with no blocking finding, on the head the agent reviewed, once CI passed there, and MUST request changes otherwise. A missing or malformed review outcome or credential MUST fail the review without posting one.                                        | T    |
| ENG-29 | P0  | A change to an invariant, or to a requirement marked for I2 review (PRV-10), MUST land only with an accepted ADR recording a named human security reviewer's approval. No B1, B2 or B3 component MAY be built past a prototype before that ADR is accepted. Prototype code MUST be provably absent from release artifacts and from every tagged release.                                                                                                                                                                                                                                                                                     | I    |
