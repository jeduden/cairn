# 10. Engineering quality (ENG)

Cairn is security-critical infrastructure written from scratch. These
requirements define the quality bar for the codebase and the delivery pipeline.

## 10.1 Code

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                 | Ver  |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| ENG-01 | P0  | The Go toolchain MUST be pinned with the `toolchain` directive. Release builds MUST use `CGO_ENABLED=0`, `-trimpath`, and embedded VCS information.                                                                                                                                                                                                                         | I    |
| ENG-02 | P0  | Code MUST be organised as `cmd/cairn` plus `internal/` packages with one responsibility each (e.g. `adapter/claudecode`, `ingest`, `provenance`, `redact`, `flag`, `store`, `cas`, `query`, `recall`, `envelope`, `landmark`, `pin`, `inject`, `kernel`, `audit`, `config`, `admin`, `mcp`, `hook`). Allowed import directions MUST be declared and enforced by a CI check. | I, T |
| ENG-03 | P0  | Packages MUST NOT hold mutable package-level state. All I/O MUST go through interfaces injectable in tests. Every blocking operation MUST take a `context.Context` with a deadline. Projection code MUST NOT read the wall clock or random sources (I10).                                                                                                                   | I, T |
| ENG-04 | P0  | Errors MUST be wrapped with `%w`; each failure class that feeds a counter (OPS-01) MUST have a typed error. Panics MUST NOT cross package boundaries; the hook and MCP entry points MUST recover, fail open, and audit.                                                                                                                                                     | I, T |
| ENG-05 | P0  | Logging MUST use `log/slog` with structured fields, and log fields MUST pass through redaction.                                                                                                                                                                                                                                                                             | T    |

## 10.2 Testing

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                          | Ver  |
| ------ | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| ENG-06 | P0  | A crash-consistency harness MUST kill Cairn processes at randomized points during ingestion, purge, migration, and rebuild — at least 10,000 iterations per nightly run — and verify all invariants after each.                                                                      | T    |
| ENG-07 | P0  | Native Go fuzzing MUST cover the transcript parser, hook input decoder, query compiler, envelope encoder, field sanitizer, redactor, and configuration parser, running continuously in nightly CI with the corpus committed. Any fuzz crash is a release blocker.                    | T    |
| ENG-08 | P0  | Property-based tests MUST cover: `seq` strictly increasing and gap-free; ingest-twice equals ingest-once; rebuild reproduces projections exactly; envelope encoding round-trips any byte sequence; sanitized fields never contain restore delimiters.                                | T    |
| ENG-09 | P0  | All tests MUST pass under the race detector. A nightly soak test MUST run 50 concurrent writers to 1M events and verify invariants.                                                                                                                                                  | T    |
| ENG-10 | P0  | Golden-file tests MUST pin the exact bytes of restore blocks and envelopes for fixture records (INJ-06).                                                                                                                                                                             | T    |
| ENG-11 | P0  | Statement coverage MUST be ≥ 90% for security-sensitive packages (`provenance`, `redact`, `flag`, `query`, `envelope`, `inject`, `pin`, `landmark`, `config`) and ≥ 80% overall.                                                                                                     | A    |
| ENG-12 | P0  | The end-to-end suite MUST run inside a network-denied sandbox and fail on any socket creation attempt (SEC-01).                                                                                                                                                                      | T    |
| ENG-13 | P1  | Mutation testing SHOULD run on security-sensitive packages with a mutation score ≥ 70%.                                                                                                                                                                                              | A    |
| ENG-14 | P0  | Tests MUST run with isolated `HOME` and `CAIRN_HOME`; a guard MUST abort any test that touches real user paths or real Claude Code configuration. The repository MUST NOT contain agent instruction files that direct agents to run destructive commands against non-isolated state. | T, I |
| ENG-15 | P0  | A benchmark suite MUST cover NFR-01..05, with a CI gate failing on a statistically significant regression greater than 10%.                                                                                                                                                          | T    |

## 10.3 Static analysis and supply chain

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                    | Ver |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| ENG-16 | P0  | CI MUST gate on `go vet`, `staticcheck`, `gosec`, `errcheck`, `govulncheck` (no reachable known vulnerabilities), and custom analyzers for: `TrustedText` construction (SEC-07), forbidden imports (`net`, `net/http`, `os/exec` outside allow-listed packages), and wall-clock or randomness use in projection code.                                          | T   |
| ENG-17 | P0  | Contract tests MUST replay recorded hook payloads and transcripts for every supported Claude Code version (NFR-11), and a nightly live end-to-end run MUST drive real Claude Code headlessly through compaction, restore, and recall.                                                                                                                          | T   |
| ENG-18 | P0  | Every direct dependency MUST be justified by an accepted ADR (ENG-26) that states its purpose, license, maintenance status and the alternatives considered, and `DEPENDENCIES.md` MUST list those ADRs. Licenses MUST be on an allow-list (Apache-2.0, MIT, BSD, ISC). The target is ≤ 10 direct dependencies. Updates MUST go through reviewed pull requests. | I   |
| ENG-19 | P0  | Release builds MUST be reproducible: two independent builders MUST produce bit-identical artifacts, verified in the release pipeline.                                                                                                                                                                                                                          | T   |
| ENG-20 | P0  | Release artifacts MUST be signed with Sigstore (keyless), carry SLSA Build Level 3 provenance and an SPDX SBOM, and be published with a signed checksum file.                                                                                                                                                                                                  | T   |

## 10.4 Process

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Ver  |
| ------ | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| ENG-21 | P0  | All changes MUST land through reviewed pull requests with signed commits and no direct pushes to the main branch. Every pull request MUST be approved by a reviewer other than its author, and that reviewer MAY be an AI agent. Changes to the requirement text (`docs/srs/`), or to what enforces it (the requirement–scenario gate, CI, the lint and coverage configuration, the agent instructions and `CODEOWNERS` itself), MUST also be approved by the stakeholder `CODEOWNERS` names. Changes to security-sensitive packages MUST have two approvals, including a designated security reviewer. AI-generated changes MUST be labelled. | I    |
| ENG-22 | P0  | Every privacy or data-flow statement in the documentation MUST reference the test that proves it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | I    |
| ENG-23 | P0  | Releases MUST follow semantic versioning, ship a changelog and upgrade notes, and test migrations from every previous minor version. Deprecations MUST last at least one minor release.                                                                                                                                                                                                                                                                                                                                                                                                                                                        | T, I |
| ENG-24 | P0  | The repository MUST contain `SECURITY.md` with a private disclosure channel and a 90-day coordinated disclosure policy. Security fixes MUST be backported to the latest minor release.                                                                                                                                                                                                                                                                                                                                                                                                                                                         | I    |
| ENG-25 | P1  | The project SHOULD have at least two active maintainers and an incident-response runbook before v1.0 general availability.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | I    |
| ENG-26 | P0  | Every design decision MUST be recorded in one ADR file under `docs/adr/`, named for its unique id, with a title, a status (proposed, accepted or superseded) and a one-line summary. A decision that changes MUST be recorded as a new ADR, and the ADR it replaces MUST be marked superseded and name its successor.                                                                                                                                                                                                                                                                                                                          | T    |
