# 7. Non-functional requirements

Reference hardware for performance targets: 2 vCPU, 4 GiB RAM, local SSD.

| ID     | Category        | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Ver |
| ------ | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- |
| NFR-01 | Latency         | Hook wall-clock time at p95 on a project with 1M events†: `UserPromptSubmit` ≤ 50 ms; `SessionStart` ≤ 150 ms; `PostToolUse`, `Stop`, `SubagentStop`, `Notification` ≤ 100 ms; `PreCompact` ≤ 2 s; `SessionEnd` ≤ 1 s. Held `PermissionRequest`: Cairn's own work ≤ 50 ms† beyond the wait, and the wait itself ≤ the owner's hold window, capped 10 s† below the harness timeout. These budgets MUST hold with the lane view open and ten harnesses writing.                                    | A   |
| NFR-02 | Latency         | Every hook MUST honour an internal deadline below the harness timeout (ASM-10) and hand off unfinished work through a work marker.                                                                                                                                                                                                                                                                                                                                                               | T   |
| NFR-03 | Latency         | MCP `search` ≤ 200 ms p95 and `expand` ≤ 100 ms p95 (excluding transfer of large payloads) at 10M events†.                                                                                                                                                                                                                                                                                                                                                                                       | A   |
| NFR-04 | Throughput      | Ingestion ≥ 5,000 events/s on one core†.                                                                                                                                                                                                                                                                                                                                                                                                                                                         | A   |
| NFR-05 | Scale           | Per project: ≥ 10M events, ≥ 100 GiB payloads, single sessions above 10M tokens, ≥ 50 concurrent sessions and subagents writing.                                                                                                                                                                                                                                                                                                                                                                 | A   |
| NFR-06 | Availability    | On any internal error, a hook MUST exit so that the harness proceeds normally, with no injection, and MUST audit the error (I9). Exceptions are limited to violations of I2, I4, or I8, which MUST fail closed.                                                                                                                                                                                                                                                                                  | T   |
| NFR-07 | Durability      | The store MUST remain consistent if any Cairn process is killed at any instruction (crash-consistency harness, ENG-06), losing at most the in-flight transaction, which is re-ingested on the next run.                                                                                                                                                                                                                                                                                          | T   |
| NFR-08 | Concurrency     | Concurrent writers MUST never corrupt the store, lose events, or produce duplicate `seq` values.                                                                                                                                                                                                                                                                                                                                                                                                 | T   |
| NFR-09 | Footprint       | The core MUST leave no resident process between sessions; per-hook peak RSS ≤ 50 MiB†; store overhead ≤ 1.5× stored text†. The lane-view, run, peer, publish and bridge components run only while the user runs them, each with peak RSS ≤ 256 MiB† and steady-state CPU ≤ 5% of one core† while idle, measured on the reference hardware; for the run component these budgets MUST hold in total for ten concurrent instances, and it MUST add at most 10 ms† p95 to keystroke-to-echo latency. | A   |
| NFR-10 | Portability     | linux/amd64, linux/arm64, darwin/arm64; single static binary (CON-02).                                                                                                                                                                                                                                                                                                                                                                                                                           | T   |
| NFR-11 | Compatibility   | Cairn MUST support the latest Claude Code release and the previous two minor versions, tolerate unknown fields and unknown event types (REC-05), and detect incompatible format changes loudly.                                                                                                                                                                                                                                                                                                  | T   |
| NFR-12 | Usability       | A new tenant MUST reach a working setup with defaults in ≤ 5 minutes via plugin install, with zero required configuration.                                                                                                                                                                                                                                                                                                                                                                       | D   |
| NFR-13 | Maintainability | Adding support for a new transcript format version MUST require changes only in the harness adapter package.                                                                                                                                                                                                                                                                                                                                                                                     | I   |
| NFR-14 | Documentation   | Operator guide, threat model, configuration reference, MCP tool reference, and upgrade notes MUST ship with every release.                                                                                                                                                                                                                                                                                                                                                                       | I   |
| NFR-15 | Latency         | On the reference hardware, for a node holding 10M events across 50 lanes, at p95: an ingested event appears in the lane view within 1 s†; Catch up paints within 1 s†; search shows first results within 300 ms†; opening a hit in context takes ≤ 150 ms†; replay steps between events within 50 ms† and rebuilds a worktree within 500 ms†. A surface that misses its target MUST say so on screen.                                                                                            | A   |
