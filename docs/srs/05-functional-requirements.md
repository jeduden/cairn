# 5. Functional requirements

Each table lists: **ID** · **Pri** · **Requirement** · **Ver** (verification
method) · **Traces** (invariants).

## 5.1 Record (REC)

| ID     | Pri | Requirement                                                                                                                                                                                                                                               | Ver | Traces  |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------- |
| REC-01 | P0  | Cairn MUST ingest Claude Code session transcripts from the configured transcript roots (default `~/.claude/projects/`).                                                                                                                                   | T   | I1      |
| REC-02 | P0  | Cairn MUST ingest subagent transcripts and link each to its parent session, recording agent identity when the transcript provides it.                                                                                                                     | T   | I1      |
| REC-03 | P0  | Ingestion MUST be incremental and idempotent: each source has a cursor (byte offset plus a hash of the consumed prefix), and re-ingesting any source MUST NOT create duplicate events.                                                                    | T   | I1, I10 |
| REC-04 | P0  | Cairn MUST attribute events to sessions from the transcript source, never from hook payload identity alone, so that hooks lacking subagent fields (ASM-06) cannot cause mis-attribution.                                                                  | T   | I1      |
| REC-05 | P0  | Lines Cairn cannot parse, or whose type it does not recognize, MUST be stored as `unparsed` events containing the redacted raw line. They MUST NOT be dropped, and MUST increment a counter.                                                              | T   | I1, I6  |
| REC-06 | P0  | Every event MUST receive a `seq` that is strictly increasing, gap-free, and never reused within its project, assigned inside the append transaction.                                                                                                      | T   | I1, I10 |
| REC-07 | P0  | If a source shrinks or its consumed prefix no longer matches the stored hash, Cairn MUST start a new source generation, retain every previously ingested event, and write an audit entry.                                                                 | T   | I1, I6  |
| REC-08 | P0  | The record MUST NOT depend on source files after ingestion. `cairn verify` MUST report any source that disappeared before it was fully ingested.                                                                                                          | T   | I1, I6  |
| REC-09 | P0  | Event content above a threshold (default 8 KiB†) MUST be stored in the content-addressed payload store keyed by SHA-256, with the event holding a preview (default ≤ 512 bytes†) and the reference. Payload writes MUST be atomic (write, fsync, rename). | T   | I1      |
| REC-10 | P0  | Events MUST form a per-project hash chain: each event stores `SHA-256(prev_hash ‖ canonical_encoding(event))`, where the canonical encoding includes the payload hash.                                                                                    | T   | I10     |
| REC-11 | P0  | Event text, including payload text up to an indexing cap (default 1 MiB† per event), MUST be indexed in SQLite FTS5.                                                                                                                                      | T   | —       |
| REC-12 | P0  | Within one source, events MUST be appended in source order. Source timestamps MUST be preserved as metadata; `seq` alone defines order.                                                                                                                   | T   | I10     |
| REC-13 | P1  | `PostToolUse` and `Stop` hooks SHOULD ingest the active transcript incrementally within their budget and leave a work marker for any remainder.                                                                                                           | T   | I9      |
| REC-14 | P1  | Cairn SHOULD ingest Claude Agent SDK transcripts from configurable roots.                                                                                                                                                                                 | T   | I1      |
| REC-15 | P1  | Cairn SHOULD support retention policies per provenance class (for example, expire untrusted payloads after N days), executed as purges with tombstones. The default policy MUST retain everything.                                                        | T   | I1, I5  |
| REC-16 | P2  | Cairn MAY import Claude Managed Agents event history.                                                                                                                                                                                                     | D   | I1      |

## 5.2 Provenance and trust (PRV)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                      | Ver | Traces |
| ------ | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --- | ------ |
| PRV-01 | P0  | Every event MUST carry exactly one provenance class from this closed set: `user`, `assistant`, `tool_call`, `tool_result:<tool>`, `web`, `mcp:<server>`, `file`, `subagent_result`, `harness_meta`, `harness_text`, `operator`, `unparsed`.                                                                                                                                                                                                      | T   | I2     |
| PRV-02 | P0  | The default trust policy MUST classify as `trusted` only: `operator`; `harness_meta` (structural lifecycle data such as timestamps, token counts, session start and end); and `user` when the deployment mode is `interactive`. Every other class MUST be `untrusted`.                                                                                                                                                                           | T   | I2     |
| PRV-03 | P0  | `assistant` and `tool_call` MUST be untrusted, because the model can reproduce injected content. `harness_text` (for example compaction summaries and system reminders) MUST be untrusted, because it can summarize untrusted content.                                                                                                                                                                                                           | T   | I2     |
| PRV-04 | P0  | Deployment mode MUST be `automation` by default, in which `user` is untrusted (prompts on runners are often generated from external content such as issue text). `interactive` mode MUST be an explicit opt-in in the tenant configuration.                                                                                                                                                                                                      | T   | I2     |
| PRV-05 | P0  | Configuration MUST NOT be able to classify any provenance class as trusted beyond PRV-02.                                                                                                                                                                                                                                                                                                                                                        | T   | I2     |
| PRV-06 | P0  | Every derived artifact (landmark, kernel output, recall result, export record) MUST record its source events and MUST be untrusted if any source is untrusted (taint propagation).                                                                                                                                                                                                                                                               | T   | I2     |
| PRV-07 | P1  | Cairn SHOULD flag untrusted events that contain instruction-like content: imperatives addressed to an assistant or AI, role or system markers, tool-call syntax, invisible or bidirectional Unicode, and base64 or similarly encoded blocks above a size threshold. Flags MUST NOT block storage. Flagged events MUST carry the flag in recall results, MUST NOT contribute text to landmarks, and MUST be listable via `cairn audit --flagged`. | T   | I5, I6 |

## 5.3 Pins (PIN)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                           | Ver | Traces |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| PIN-01 | P0  | Active pins MUST be created only by trusted actions: the operator CLI (`cairn pin add`), a `/pin` slash command issued by a trusted `user` (interactive mode only), or pin entries in tenant configuration.                                                                                                           | T   | I2, I3 |
| PIN-02 | P0  | Claude MUST NOT be able to create or activate pins. A pin proposed through MCP (`pins_propose`, P1) MUST be stored as an inactive candidate with provenance `assistant`.                                                                                                                                              | T   | I2     |
| PIN-03 | P0  | Each pin MUST store: verbatim text (≤ 1,000 characters†), type, priority, creating event `seq`, author, and text hash.                                                                                                                                                                                                | T   | I3     |
| PIN-04 | P0  | Pins MUST be immutable. Changing a pin MUST be recorded as a removal event followed by an addition event.                                                                                                                                                                                                             | T   | I10    |
| PIN-05 | P1  | Cairn SHOULD detect candidate constraints in trusted `user` turns (for example "never…", "always…", "do not…") and record them as inactive candidates. Candidates MUST become active only through trusted confirmation. In `automation` mode, candidates MUST NOT be activated automatically under any configuration. | T   | I2, I3 |
| PIN-06 | P0  | Pin types MUST follow the Knowledge Triage model (`constraint`, `preference`, `decision`, `fact`, `episode`). Only `constraint` and `preference` pins MUST be injected automatically in v1.                                                                                                                           | T   | I3     |
| PIN-07 | P1  | If ASM-01/02 permit, the `PreCompact` hook SHOULD return fixed compaction guidance instructing that user-stated constraints be preserved verbatim. The guidance MUST be static text and MUST NOT contain record content.                                                                                              | T   | I2, I3 |
| PIN-08 | P0  | If active pins exceed the pin budget (default 1,000 tokens†), Cairn MUST inject pins in order of priority then `seq`, MUST NOT truncate text within a pin, MUST state in the restore block how many pins were omitted, and MUST write an audit entry.                                                                 | T   | I3, I6 |
| PIN-09 | P1  | `cairn doctor` SHOULD warn when a pin duplicates text already present in the project's `CLAUDE.md` files, since the harness loads those itself.                                                                                                                                                                       | T   | —      |

## 5.4 Recall (RCL)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                  | Ver | Traces |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| RCL-01 | P0  | Cairn MUST provide an MCP server exposing the tools `search`, `expand`, `get`, `landmarks`, `pins_list`, and `stats`, as specified in §9.2.                                                                                                                                                  | T   | I1     |
| RCL-02 | P0  | `search` MUST accept filters for session, time range, provenance class, event kind, and trust level, and MUST return at most `k` hits (default 10, maximum 50†) ranked by BM25 with length normalization and per-session damping so that long sessions cannot crowd out relevant short ones. | T   | —      |
| RCL-03 | P0  | `expand` (by `seq` range) and `get` (by `seq`) MUST return exact post-redaction content, resolving payload references, subject to a per-call token cap (default 8,000†) with a continuation cursor.                                                                                          | T   | I1     |
| RCL-04 | P0  | All recalled content MUST be returned inside the envelope defined in §9.3.                                                                                                                                                                                                                   | T   | I2     |
| RCL-05 | P0  | Recall scope MUST default to the current project. Cross-project recall MUST NOT be possible in v1. Widening from the current session to all sessions of the project MUST require an explicit parameter and MUST be logged.                                                                   | T   | I8     |
| RCL-06 | P0  | Quarantined events and artifacts MUST never be returned. Purged ranges MUST return a tombstone notice instead of content.                                                                                                                                                                    | T   | I5     |
| RCL-07 | P0  | Every recall call MUST be appended to the record as an event (provenance `assistant` for the query, with the returned `seq` set), so recall activity is auditable and drives the recall-taint signal (SEC-13).                                                                               | T   | I6     |

## 5.5 Landmarks (LMK)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                        | Ver | Traces |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| LMK-01 | P0  | Cairn MUST segment each session into spans, starting a new span at every user turn, compaction, and subagent start or end. Span boundaries MUST be a deterministic function of the record.                                                                                                         | T   | I10    |
| LMK-02 | P0  | Cairn MUST produce one landmark per closed span containing only structural fields: `seq` range, turn range, event counts by kind, tool names with call counts, touched file paths, and an error indicator. In `interactive` mode it MAY include the first 80† characters of the trusted user turn. | T   | I2     |
| LMK-03 | P0  | Every structural field that can be influenced by untrusted input (file paths, tool names, MCP server names) MUST be sanitized to an allow-listed character set (`A–Z a–z 0–9 . _ / @ : + -`) and a maximum length (default 80†); non-conforming values MUST be replaced with `<field:HASH8>`.      | T   | I2     |
| LMK-04 | P0  | Flagged and quarantined events MUST contribute only to counts, never to text fields.                                                                                                                                                                                                               | T   | I2, I5 |
| LMK-05 | P0  | Landmarks MUST roll up into tiers of at most `k` blocks (default 8†): when a tier fills, the newest block keeps full detail and the older blocks collapse to one line each and merge into the next tier, bounding the index to O(k · log_k n) blocks.                                              | T   | I10    |
| LMK-06 | P2  | Cairn MAY generate natural-language headlines for spans whose every event is trusted.                                                                                                                                                                                                              | T   | I2     |

## 5.6 Restore and injection (INJ)

| ID     | Pri | Requirement                                                                                                                                                                                                                             | Ver  | Traces |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ------ |
| INJ-01 | P0  | On `SessionStart` with `source = compact`, Cairn MUST return a restore block containing: active pins (PIN-06, PIN-08), the landmark index for the current session, and a one-line statement that recall tools are available.            | T    | I3     |
| INJ-02 | P0  | On `SessionStart` with `source` = `startup`, `resume`, or `clear`, Cairn MUST by default return active pins and, if the project has history, the recall statement. Including the landmark index MUST be configurable.                   | T    | I3     |
| INJ-03 | P0  | The restore builder MUST accept only values of type `TrustedText`. `TrustedText` MUST be constructible only inside the injection package, only from active pins and sanitized structural fields, enforced by an unexported constructor. | I, T | I2     |
| INJ-04 | P0  | Injection on `UserPromptSubmit` MUST be disabled by default. If enabled, it MUST be limited to `TrustedText` and every injection MUST be audited.                                                                                       | T    | I2     |
| INJ-05 | P0  | If Cairn cannot determine unambiguously which session a hook belongs to (ASM-06), it MUST inject pins only.                                                                                                                             | T    | I9     |
| INJ-06 | P0  | For identical record state, the restore block MUST be byte-identical: stable ordering, no timestamps, no absolute paths, no random identifiers.                                                                                         | T    | I10    |
| INJ-07 | P0  | The restore block MUST respect a total budget (default 2,000 tokens†). When over budget, Cairn MUST remove landmark detail deterministically, coarsest tier last, and MUST NOT reduce pins below the PIN-08 rule.                       | T    | I9     |
| INJ-08 | P0  | The restore block MUST use fixed delimiters, and no injected field may contain the delimiter sequences (guaranteed by construction of `TrustedText`).                                                                                   | T    | I2     |
| INJ-09 | P0  | Content with provenance `harness_text` (including compaction summaries) MUST NOT appear in any restore block.                                                                                                                           | T    | I2     |

## 5.7 Compute kernel (CMP)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                      | Ver  | Traces |
| ------ | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---- | ------ |
| CMP-01 | P1  | Cairn SHOULD expose MCP tools `kernel_exec`, `kernel_vars`, and `kernel_reset`, backed by a hermetic Starlark interpreter (ADR-04).                                                                                                                                                              | T    | —      |
| CMP-02 | P1  | Each session MUST have a persistent namespace that survives across `kernel_exec` calls until `kernel_reset`, worker restart, or session end.                                                                                                                                                     | T    | —      |
| CMP-03 | P1  | The kernel MUST provide read-only built-ins `cairn.search`, `cairn.expand`, `cairn.get`, and `cairn.landmarks` that return structured values, plus `json`, regular-expression, math, and time helpers.                                                                                           | T    | —      |
| CMP-04 | P1  | The kernel MUST have no access to the filesystem, network, processes, clock-driven nondeterminism beyond provided helpers, or environment variables.                                                                                                                                             | I, T | I4     |
| CMP-05 | P1  | Each execution MUST run in a `cairn kernel-worker` child process with a step budget, a wall-clock limit (default 10 s†), and a memory limit (default 512 MiB† via OS resource limits). Exceeding a limit MUST return an error result, restart the worker, and state that the namespace was lost. | T    | I9     |
| CMP-06 | P1  | Only explicit `print` output MUST return to Claude, capped (default 8,000 tokens†) with a truncation notice stating that variables persist. The output MUST be enveloped and tainted by every record read during the execution.                                                                  | T    | I2     |
| CMP-07 | P1  | Kernel reads MUST honour quarantine and recall scope exactly as MCP recall does.                                                                                                                                                                                                                 | T    | I5, I8 |
| CMP-08 | P2  | Cairn MAY support an external Python kernel as an opt-in, sandboxed, network-less worker with read-only store access.                                                                                                                                                                            | T    | I4     |
| CMP-09 | P2  | Parallel model sub-calls over record data MAY be supported only through harness mechanisms (for example subagents). Cairn MUST NOT call model APIs itself.                                                                                                                                       | I    | I4     |

## 5.8 Administration and lifecycle (ADM)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                     | Ver | Traces  |
| ------ | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------- |
| ADM-01 | P0  | Cairn MUST be distributable as a Claude Code plugin that registers its hooks and MCP server, together with the static binary (ADR-06).                                                                                                                                          | D   | I7      |
| ADM-02 | P0  | `cairn install` (fallback path) MUST display a diff of every configuration change and require confirmation or `--yes`. `cairn uninstall` MUST reverse exactly the changes `install` made.                                                                                       | T   | I7      |
| ADM-03 | P0  | Cairn MUST detect managed settings and MUST NOT write to or override them. Installation through managed settings or the runner image MUST be supported and documented.                                                                                                          | T   | I7      |
| ADM-04 | P0  | Configuration MUST be TOML with strict validation: unknown keys, type errors, and out-of-range values MUST fail with a precise error. Layers are defaults, then tenant config, then project `.cairn.toml`.                                                                      | T   | I6      |
| ADM-05 | P0  | Schema changes MUST be versioned forward-only migrations, preceded by an automatic verified backup. Cairn MUST refuse to open a store with a newer schema than it supports.                                                                                                     | T   | I1      |
| ADM-06 | P0  | `cairn backup` and `cairn restore` MUST produce and restore consistent copies of the store and payloads using SQLite's online backup, verified with `cairn verify` after restore.                                                                                               | T   | I1      |
| ADM-07 | P0  | `cairn purge` MUST delete the selected scope (project, session, `seq` range, time window, or provenance class) from events, FTS index, projections, and payload store, append a tombstone event per purged range, and compact the database. `cairn uninstall` MUST offer purge. | T   | I1, I5  |
| ADM-08 | P0  | `cairn rebuild` MUST regenerate all derived state from the record, and a subsequent `cairn verify` MUST confirm it is byte-identical to the state before rebuild.                                                                                                               | T   | I10     |
| ADM-09 | P0  | `cairn verify` MUST check source completeness (REC-08), hash-chain integrity, payload integrity, and projection consistency, exiting non-zero on any failure.                                                                                                                   | T   | I6, I10 |
| ADM-10 | P0  | `cairn doctor` MUST be read-only by default. `cairn doctor --fix` MUST show each change before applying it.                                                                                                                                                                     | T   | I7      |
| ADM-11 | P0  | `cairn status` MUST always show store locations, sizes, schema version, deployment mode, and non-zero failure counters.                                                                                                                                                         | T   | I6      |
| ADM-12 | P1  | `cairn export --trusted-only` SHOULD write trusted events with full provenance as JSONL for downstream systems.                                                                                                                                                                 | T   | I2      |

## 5.9 Boundary to durable memory (MEM)

| ID     | Pri | Requirement                                                                                              | Ver  | Traces |
| ------ | --- | -------------------------------------------------------------------------------------------------------- | ---- | ------ |
| MEM-01 | P0  | Cairn MUST NOT promote record content into any long-term memory, summary store, or cross-project store.  | I, T | I2     |
| MEM-02 | P1  | Downstream memory systems SHOULD consume Cairn only through ADM-12, applying their own promotion policy. | I    | I2     |

## 5.10 Observability (OPS)

| ID     | Pri | Requirement                                                                                                                                                                                   | Ver | Traces |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| OPS-01 | P0  | Every failed, dropped, rejected, redacted, timed-out, or truncated operation MUST append an entry to the audit log and increment a named counter derived from it.                             | T   | I6     |
| OPS-02 | P0  | The audit log MUST be append-only JSONL with its own hash chain, created `0600`, rotated with chain continuation.                                                                             | T   | I6     |
| OPS-03 | P0  | `cairn doctor` MUST exit non-zero while any failure counter has increased since the last operator acknowledgement (`cairn ack`).                                                              | T   | I6     |
| OPS-04 | P1  | Cairn SHOULD provide an end-to-end canary (`cairn canary`) that writes a marker through the hook path and recalls it through MCP, exiting non-zero on failure, runnable in CI and on runners. | T   | I6     |
| OPS-05 | P1  | Cairn SHOULD emit structured logs (`log/slog`, JSON) to a file or stderr, suitable for collection by an external agent. Cairn itself MUST NOT ship logs anywhere.                             | T   | I4     |
