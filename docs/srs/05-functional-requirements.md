## 5.2 Provenance and trust (PRV)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Ver  | Traces |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ------ |
| PRV-01 | P0  | Every event MUST carry its writer and exactly one provenance class from this closed set: `user`, `assistant`, `tool_call`, `tool_result:<tool>`, `web`, `mcp:<server>`, `file`, `subagent_result`, `harness_meta`, `harness_text`, `operator`, `post`, `unparsed`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | T    | I2     |
| PRV-02 | P0  | The default trust policy MUST classify as `trusted` only: events a writer of this node wrote in class `operator`, `harness_meta`, or `user` when the deployment mode is `interactive`; and `operator` events trusted under PRV-10. Every other event MUST be `untrusted`, including every event another tenant wrote, every non-`operator` event from another node, every `post`, and every event ingested from a transcript the hooks did not report (REC-22). A widening `operator` event (OWN-11) MUST take effect in derived state (restore blocks, rule levels, grants, trust, enrolments) only when the sandbox states and risk acceptance recorded when it was written permitted it under OWN-22, and, where an authenticator was required, its stored assertion verifies; `cairn verify` MUST report every widening event that fails either.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | T    | I2, I8 |
| PRV-03 | P0  | `assistant` and `tool_call` MUST be untrusted, because the model can reproduce injected content. `harness_text` (for example compaction summaries and system reminders) MUST be untrusted, because it can summarize untrusted content.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | T    | I2     |
| PRV-04 | P0  | Deployment mode MUST be `automation` by default, in which `user` is untrusted (prompts on runners are often generated from external content such as issue text). `interactive` mode MUST be an explicit opt-in in the tenant configuration.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | T    | I2     |
| PRV-05 | P0  | Configuration MUST NOT be able to classify any provenance class as trusted beyond PRV-02.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | T    | I2     |
| PRV-06 | P0  | Every derived artifact (landmark, kernel output, recall result, export record) MUST record its source events and MUST be untrusted if any source is untrusted (taint propagation).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | T    | I2     |
| PRV-07 | P1  | Cairn SHOULD flag untrusted events that contain instruction-like content: imperatives addressed to an assistant or AI, role or system markers, tool-call syntax, invisible or bidirectional Unicode, and base64 or similarly encoded blocks above a size threshold. Flags MUST NOT block storage. Flagged events MUST carry the flag in recall results, MUST NOT contribute text to landmarks, and MUST be listable via `cairn audit --flagged`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | T    | I5, I6 |
| PRV-09 | P0  | An event's writer MUST be derived from the key that verifiably signed or wrote it on this node, never from a field in the event or bundle. Cairn MUST refuse and audit any imported event or segment that claims a writer of the importing node, or whose verified key is not a writer the bundle or peer declared.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | T    | I2, I8 |
| PRV-10 | P2  | An owner key MUST certify each device key with a scope, drawn from a closed set of owner-act kinds, and a maximum rule level (OWN-10). A device key MAY hold a delegation to certify writer keys for one repository, so sandboxes and new sessions chain owner → device → writer while the owner key stays offline. A sandbox token key (PEER-06), certified by a device key holding that delegation and limited to the token's project, lanes and expiry, MUST be admitted as a link between device and writer; revoking the token MUST revoke every writer it certified. An `operator` event from another node MUST be trusted only when its key chains to this tenant's owner key, the act lies within the scope and the rule level, and the key is not revoked. Once a node holds a revocation, it MUST refuse every event by the revoked key that it did not already hold, unless a seal it held before the revocation covers it, whatever heads the event cites; the revocation MUST extend to every key and certificate the revoked key issued that the node did not hold before it. Revocations MUST be signed events that replicate like any other. A phone's scope MUST be limited to allowing or denying held permission requests. This requirement MUST pass a recorded I2 security review before it ships (ENG-29). | T, I | I2, I8 |
