# 5. Functional requirements: room view

The room-view family of §5, kept in its own file. Each table lists:
**ID** · **Pri** · **Requirement** · **Ver** (verification method) ·
**Traces** (invariants).

## 5.12 Room view (VIEW)

VIEW holds what a person reads, on every surface: the browser room
view (the room-view component, B1), the TUI, the CLI and the phone.
VIEW has no write path; every act a person takes is in OWN. The
priorities of rows that open the room view to v1 are provisional until
OQ-30 settles the v1 scope.
