| PRV-08 | P0  | Cairn MUST derive an event's provenance from its transcript line's structural fields (line, attachment and content block type, `isMeta`, and the tool call a tool result answers), never from its `renderedRole`. A transcript line MUST be classified `user` only when it contains text typed at the harness's input; a tool result is not, and an `isMeta` line, command output the harness writes as a `user` line, a line the launcher carried in (LANE-14) and free text a line carries outside a message MUST be untrusted `harness_text`, never `harness_meta`. A subagent's delegated task, which its transcript carries as a `user` line, MUST be classified untrusted `harness_text`, never `user` (OWN-24). | PRV-10 | P1  | A person, another service account or managed policy listing it MUST certify a service account's principal key, marking whether the account relays text others wrote, an unmarked listing counting as relaying, and only that certifier MAY revoke it, managed policy by no longer listing it; a service-account certificate MUST count only once the certified principal key countersigns it, and each managed-policy listing and each removal MUST be recorded as a structural event that enters the key set of the node that recorded it from its machine's managed policy, and another node's only once the listed principal key countersigns the listing, a removal wherever the listing it ends entered (open for another principal's node: OQ-41); only a principal key never certified counts as a person's. A principal key, never kept by a Cairn component, MUST certify each device key with a device scope and a maximum rule level. On a token-key-only node, its token key MUST certify each seat key in place of a device key (PRV-11). A device, token or seat certificate MUST count only once the key it certifies countersigns it, and a key whose countersigned certificates chain it to two principal keys MUST chain to neither, its seat a member of no room (LANE-25). Revoking an access token MUST revoke every seat key its token key certified. A principal act another node's device key signed, or a post or pin from a device seat it certified, MUST be trusted only when that key chains, never through another principal key, to the principal key of this node's principal, or, for a post or pin, of a principal its trust grant covers, the act, post or pin lies within the scope and the rule level, and the key is not revoked. Once a node holds a revocation, it MUST refuse every event by the revoked key that it did not already hold, unless a seal it held before the revocation covers it, whatever heads the event cites; the revocation MUST extend to every key and certificate the revoked key issued that the node did not hold before it. Revocations MUST be signed events that replicate like any other (open for another principal's node: OQ-41). A paired phone's scope MUST be limited to reading and to allowing or denying held permission requests. A paired phone's device key MUST certify its device seat's key (open: OQ-39). A token-key-only node MUST sign no principal or expire acts, and every pin it writes MUST restore only once stamped. This requirement MUST pass a recorded I2 security review before it ships. | T, I | I2, I8 |
