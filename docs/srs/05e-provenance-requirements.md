| PRV-10 | P1  | A person, another service account or managed policy listing it MUST certify a service account's principal key, marking whether the account relays text others wrote, an unmarked listing counting as relaying, and only that certifier MAY revoke it, managed policy by no longer listing it; a service-account certificate MUST count only once the certified principal key countersigns it, and each managed-policy listing and each removal MUST be recorded as a structural event that enters the key set of the node that recorded it from its machine's managed policy, and another node's only once the listed principal key countersigns the listing, a removal wherever the listing it ends entered (open for another principal's node: OQ-41); only a principal key never certified counts as a person's. Once a node holds a revocation, it MUST refuse every event by the revoked key that it did not already hold, unless a seal it held before the revocation covers it, whatever heads the event cites; the revocation MUST extend to every key and certificate the revoked key issued that the node did not hold before it. Revocations MUST be signed events that replicate like any other (open for another principal's node: OQ-41). A paired phone's scope MUST be limited to reading and to allowing or denying held permission requests. A paired phone's device key MUST certify its device seat's key (open: OQ-39). | PRV-12 | P0  | A node's device keys, or on a token-key-only node its token keys, MUST form key event logs of structural key events, each recorded in a device seat in the node's personal room that a key of its log certified; only the key events this node recorded, none an arrival event names (REC-26), count, and a void one counts for nothing. A key event MUST carry only its kind (`minted`, `token key adopted`, `minted anew`, `rotated` or `recovered`), the key's fingerprint, the digest of its recovery key's public key, the digest of the key event it follows in its log, the fingerprint of each key it replaces and its signatures; a rotation also its recovery key's public key and the chain head of the device seat writer that recorded the key event it follows, a `recovered` the digest of the inception it joins, and a `token key adopted` its token certificate, which MUST name the token key it succeeds (PEER-06). An inception (`minted`, `token key adopted` or `minted anew`) starts a log and follows none. The node's genesis log is the one whose inception is the first event of the device seat that created its personal room, a carried-over home's earlier key events counting as this node's for finding it alone; a `minted anew` that a backup restore's principal act names starts the current key event log in place of every log before it (ADM-06). Any other `minted` or `token key adopted` MUST directly follow a node identity change event in its writer and replaces the key that event names (REC-24), and any other `minted anew` replaces the missing device key it names; a `token key adopted` whose key an earlier key event names is void. A rotation (`rotated` or `recovered`) MUST follow a key event of its log, carry the recovery key that event committed to, be signed by it, and name as the new key one freshly minted, on the node or, for a token key, by the node that issued the later access token carrying the recovery key (`cairn access-token rotate`), never the recovery key itself; a `rotated` MUST also be signed by the key it replaces, and a `recovered` MUST name a `minted anew` inception that replaced the key it replaces, joining that inception's log to its own and voiding that inception's recovery key. Voidness is decided first, in hash-link order from each inception on: a key event that breaks these rules is void, and so is an inception whose replaced key a key event of its own log follows, unless a `recovered` rotation names it. A log's newest key event is one no counting key event follows; a log with two is in duplicity, and so are two counting inceptions that replace one key, in whichever of this node's device seats each was recorded. The current key event log is the genesis log, followed through its rotations and through the counting inception that replaces its newest key; its keys are those from its last such inception on, and those of a log a `recovered` rotation joined. A log other than the genesis log MUST certify no `witnessed` writer (REC-26) until a `recovered` rotation joins it, `cairn device-key confirm`, a widening principal act at the controlling terminal (OWN-11, OWN-12), names its inception, or, for a token key, the device key that made the token certificate of the token key it succeeds made its token certificate. Under duplicity, no key after it MAY certify a `witnessed` writer until `cairn device-key choose`, such a principal act, chooses the branch to keep, or, for two inceptions, a rotation of the log whose key they replace voids both. Revoking a key on the current key event log (SEC-27) MUST leave every writer it certified before the revocation `witnessed`, and a certificate record after the revocation, in the writer that holds it, MUST count for nothing. Each seat certificate a key makes MUST be recorded by its digest, as a structural certificate record, in the device seat writer that recorded its log's newest key event, and MUST count for `witnessed` only while no rotation has replaced its key, or when it lies at or before the chain head that rotation carries. A recovery key MUST be minted with each inception and rotation. A device key's MUST be kept in its own entry, as SEC-10 keeps the device key, never logged, exported, backed up or placed in a segment, until `cairn device-key write-recovery-key`, a widening principal act at the controlling terminal, writes it once to a new file the principal names outside every worktree and the Cairn home, created exclusively and readable only by the principal's OS user, encrypted under a key a memory-hard function derives from a passphrase typed there, reads the file back, checks it against the committed digest and only then erases the key from the node; that principal act MUST NOT name the file. `cairn device-key rotate`, a widening principal act at the controlling terminal, MUST read the key from such a file, check it against the committed digest and erase it from memory once it has signed. Each such principal act MUST be recorded (`operator`) before its key event (`structural`). A token key's recovery key MUST be minted and kept by the node that issued its access token as that node keeps its device key, and erased there, audited, once that access token expires or is revoked; on its way it is protected only as well as the later access token that carries it. Cairn MUST audit and count every key event, every void one, every failed or interrupted write or read of a recovery key, every duplicity and every change of the current key event log; `cairn status` and `cairn verify` MUST show the current key event log's inception kind, or each branch under duplicity, each log that certifies no `witnessed` writer yet, each void key event and each duplicity, and `cairn status` each recovery key still on the node. | T    | I2, I6, I10 |
