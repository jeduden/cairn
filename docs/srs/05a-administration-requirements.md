# 5. Functional requirements: administration, memory and observability

## 5.8 Administration and lifecycle (ADM)

| ID     | Pri | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Ver | Traces     |
| ------ | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ---------- |
| ADM-01 | P0  | Cairn MUST be distributable as a Claude Code plugin that registers its hook handlers and MCP server, together with the core executable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | D   | I7         |
| ADM-02 | P0  | `cairn install` MUST display a diff of every harness configuration change and require confirmation or `--yes`, and create the node's personal room as the principal's device seat's first act. `cairn uninstall` MUST list every artifact any Cairn component created (hook, plugin and MCP registrations, LANE-28's commit hook, room-view secrets, launcher endpoints, seat and device keys, enrollments, git-carrier refs, every other file Cairn wrote outside the store, whose content only the purge it offers removes (ADM-07)), offer to remove each, reverse exactly the harness configuration changes `install` made, and audit what it left.                                                                                                                                                                                                                                                                                                                                                                                                                                           | T   | I7, I6     |
| ADM-03 | P0  | Cairn MUST detect the harness's managed settings and MUST NOT write to or override them. Installation through the harness's managed settings or the runner image MUST be supported and documented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | T   | I7         |
| ADM-04 | P0  | Every settings layer MUST be TOML with strict validation: unknown keys, type errors and out-of-range values MUST fail with an error naming the key and the problem. Defaults apply first, then configuration, repository configuration and managed policy, which overrides all three. Managed policy MUST be read from a documented system path per OS that the principal cannot write. When that file or its directory is writable by the principal, or the file is unparsable or invalid, Cairn MUST refuse to start a B1–B3 component, keep the core recording, and audit and count the condition. A settings change that adds, edits or unpins a pin that restores, changes the deployment mode or a retention policy, loosens redaction, recall scope, rule levels or hold windows, or turns on a B1–B3 component MUST be accepted only from the principal's configuration after the widening principal act accepting it records its digest, or from managed policy, which never turns a B1–B3 component on; a repository configuration key making one MUST be ignored, audited and counted. | T   | I6, I7     |
| ADM-05 | P0  | Format changes to segments and schema changes to derived artifacts MUST be versioned forward-only migrations, preceded by an automatic verified backup under ADM-06. Cairn MUST refuse to open a segment or store with a newer version than it supports.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | T   | I1         |
| ADM-06 | P0  | `cairn backup create` MUST capture the sealed segments, the open segment up to a fresh seal, the payload store, derived artifacts and the audit log with its hash chain as one consistent copy, without seat, device, token or at-rest keys, and record each backup as an audited event. A backup restore MUST be a widening principal act, verify the copy and its audit chain with `cairn verify`, reinstate the segments, payloads and derived artifacts the copy contains, reapply every purge, revocation, quarantine, unpin, unstamp and rule level tightening recorded after the backup was taken or refuse, start a new seat and writer for every local writer the copy contains, audited, never append to a reinstated writer's log or reuse a `seq`, and pass `cairn verify` afterwards.                                                                                                                                                                                                                                                                                                | T   | I1, I6     |
| ADM-07 | P0  | `cairn purge` MUST delete the selected scope (room, run, seat or writer, author, address range, time window, or provenance class) from the sealed segments, events, search index, derived artifacts and payload store, erase the commitment key and payload reference of every purged event and every copy SEC-31 names, append a tombstone per purged range containing only addresses, counts, reason and commitments, and vacuum the store and rewrite the affected segments keeping their seals verifiable. `cairn uninstall` MUST offer purge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | T   | I1, I5     |
| ADM-08 | P0  | `cairn rebuild` MUST regenerate all derived artifacts from the record, and a subsequent `cairn verify` MUST confirm it is byte-identical to the state before rebuild. Derived artifacts MUST depend only on the set of writer logs held and the node's key set, never on the order in which logs or segments arrived.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | T   | I10        |
| ADM-09 | P0  | `cairn verify` MUST check transcript source completeness, hash-chain integrity, payload integrity, and derived-artifact consistency, exiting non-zero on any failure.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | T   | I6, I10    |
| ADM-10 | P0  | `cairn doctor` MUST be read-only by default. `cairn doctor --fix` MUST show each change before applying it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | T   | I7         |
| ADM-11 | P0  | `cairn status` MUST show store locations, sizes, schema version, deployment mode, and non-zero failure counters.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | T   | I6         |
| ADM-12 | P1  | `cairn export --trusted-only` SHOULD write trusted events with full provenance as JSONL.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | T   | I2         |
| ADM-13 | P0  | Cairn MUST NOT write to any git repository or worktree (objects, refs, notes, git configuration, git hooks or files), except the harness settings file that `cairn install --scope project` writes after confirmation, the commit hook, and the git carrier's entries in a namespaced location of the clone, for a remote its node's principal and a room its owner enabled, and the launcher's fresh checkouts and new worktrees outside the run's worktree, adding no ref to its repository.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | T   | I7         |
| ADM-14 | P1  | `cairn purge` MUST accept a seat scope and `--principal <principal>`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | T   | I1, I5     |
| ADM-15 | P1  | Cairn MUST enforce configurable quotas (`quota.*`) per room, node, writer received from a peer, peer and worktree checkpoint, refuse and audit anything received over one, and never drop an accepted event to free space. This node's own recording over a quota MUST raise a failure counter and a Needs you item and keep recording.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | T   | I6, I9, I1 |
| ADM-16 | P1  | `cairn status` and `cairn doctor` MUST report, for every B1–B3 component: whether managed policy permits it, whether it runs, and its failure counters; for peers, the sync lag per writer; every writer chain ended without a closed segment; and each boundary's state and managed policy's lock.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | T   | I6         |

## 5.9 Boundary to durable memory (MEM)

| ID     | Pri | Requirement                                                                                          | Ver  | Traces |
| ------ | --- | ---------------------------------------------------------------------------------------------------- | ---- | ------ |
| MEM-01 | P0  | Cairn MUST NOT promote record content into any long-term memory, summary store, or cross-room store. | I, T | I2     |
| MEM-02 | P1  | Downstream memory systems SHOULD consume Cairn only through ADM-12.                                  | I    | I2     |

## 5.10 Observability (OPS)

| ID     | Pri | Requirement                                                                                                                                                                 | Ver | Traces |
| ------ | --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------ |
| OPS-01 | P0  | Every failed, dropped, rejected, redacted, timed-out, truncated or coalesced operation MUST append an entry to the audit log and increment a named counter derived from it. | T   | I6     |
| OPS-02 | P0  | The audit log MUST be append-only JSONL with its own hash chain, created `0600`, rotated with chain continuation.                                                           | T   | I6     |
| OPS-03 | P0  | `cairn doctor` MUST exit non-zero while any failure counter has increased since the node's principal last acknowledged them (`cairn counter ack`).                          | T   | I6     |
| OPS-04 | P1  | Cairn SHOULD provide `cairn canary`, which writes a canary event through the hook path, recalls it through MCP and exits non-zero on failure.                               | T   | I6     |
| OPS-05 | P1  | Cairn SHOULD emit structured logs (JSON) to a file or stderr. Cairn itself MUST NOT ship logs anywhere.                                                                     | T   | I4     |
| OPS-06 | P1  | Every B1–B3 component MUST append every operation OPS-01 names to the home's audit log and increment its named counter. No failure MAY be visible only in a browser.        | T   | I6     |
