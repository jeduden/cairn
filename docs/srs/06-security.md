# 6. Security

## 6.1 Threat model

### Assets

| Asset                         | Why it matters                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| Record content                | Contains code, conversations, tool output, and possibly secrets that escaped redaction |
| Pins                          | Directly shape agent behaviour after every compaction                                  |
| Restore channel               | Text Cairn places into the model's context without a tool call                         |
| Recall channel                | Text Claude pulls into context on request                                              |
| Agent configuration           | Hooks and MCP registrations control what runs in every session                         |
| Cairn binary and dependencies | Runs inside every session                                                              |

### Actors

| Actor                                            | Capability                                                                                                       | In scope                                                                                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| External content author                          | Controls text Claude reads: web pages, repositories, issues, dependency READMEs, file names                      | Yes — primary threat                                                                                                                                                       |
| Malicious or compromised MCP server              | Controls its tool results and tool names                                                                         | Yes                                                                                                                                                                        |
| Other tenant on a shared host                    | Separate OS user on the same machine                                                                             | Yes                                                                                                                                                                        |
| Repository author                                | Controls project files, including `.cairn.toml` and `CLAUDE.md`                                                  | Yes                                                                                                                                                                        |
| Supply-chain attacker                            | Targets Cairn's dependencies, build, or release                                                                  | Yes                                                                                                                                                                        |
| Process running as the same OS user              | Can read the tenant's files, open a pty, start Cairn's own components, read a terminal's screen and inject input | **For owner acts only** — an agent running unsandboxed as the tenant. A sandbox removes it; for an unsandboxed session the owner accepts the residual risks below (OWN-22) |
| Co-author or enrolled peer                       | Writes posts and segments into a shared room                                                                     | Yes                                                                                                                                                                        |
| Network attacker between peers                   | Observes or alters B2 and B3 traffic                                                                             | Yes                                                                                                                                                                        |
| Web page in the tenant's own browser             | Reaches loopback ports from the browser                                                                          | Yes                                                                                                                                                                        |
| Root on the host, compromised Claude Code binary | Full control                                                                                                     | **No**                                                                                                                                                                     |

### Residual risks

These risks remain while an agent runs unsandboxed as the tenant's own OS
user, and no rule in Cairn removes them. A sandbox that blocks them removes
them; for an unsandboxed session the owner accepts those left open (OWN-22).

| #   | Residual risk                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------- |
| R1  | The agent types into the harness's own prompt to approve itself                                                                 |
| R2  | The agent edits the harness's settings or hooks, or replaces Cairn's executables                                                |
| R3  | The agent deletes or rolls back `CAIRN_HOME`, or signs events with the writer key; only a receipt kept off the machine shows it |
| R4  | The agent shows a harmless screen while a widening act waits for confirmation                                                   |
| R5  | The agent reads every room from the store or its own room-view component, unenveloped                                           |
| R6  | The agent uses cut acts (stop, deny, quarantine) against other agents; audited, not prevented                                   |
| R7  | The agent passes a terminal-confirmation opt-in, by design                                                                      |

## 6.3 Boundary register

Every Cairn component, process and protocol, with its boundary, or the
reason it is rejected (rows X1 to X8) (SEC-19). Each component is a role
with one boundary: the core in B0, the room-view and run components in
B1, the peer component in B2, the publish and bridge components in B3.
Whether they ship in one executable or several is not decided (OQ-32),
and no packaging may change a row. Rows 24 and 25 are not Cairn's
processes; they are listed so the register is complete, and SEC-19 does
not assign them. "Lock" means managed policy can disable the row
(SEC-22). The Reach column states what each row may do, not how it does
it. CI checks the register against build-time evidence of each
component's reach and against its sandboxed tests.
